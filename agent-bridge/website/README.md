# ArcLink website

A standalone Chinese landing page for ArcLink. Plain HTML, CSS and JavaScript; no framework, package installation, backend or Tauri bridge required.

## Preview

From the repository root:

```sh
python3 agent-bridge/website/prepare.py
python3 -m http.server 8767 --bind 127.0.0.1 --directory agent-bridge/website
```

Open <http://127.0.0.1:8767>. Preparation uses the committed versioned R2 links in `downloads.json` and does not make network requests. Legacy local-package configuration still requires the indicated DMG and fails clearly if it is absent. The page and download work without JavaScript. The small JS module only enhances native FAQ accordions.

## Editing and downloads

- Edit `index.template.html` for content and `styles.css` for presentation. `index.html` is generated by `prepare.py` and committed for convenient preview. Regenerate it after editing the template or configuration.
- `downloads.json` is the single source for the displayed Mac version, minimum OS and both architecture downloads. `mac.packages.arm64` and `mac.packages.x64` use exact versioned HTTPS R2 DMG URLs under `https://download.classktv.com/releases/arclink-vX.Y.Z/`; optional `sizeBytes` is displayed per button. Preparation validates version/architecture consistency and rejects credentials, query strings and alternate origins.
- To generate the page for a new mirrored release, use a **validated local R2 manifest**, rather than fetching a mutable endpoint during a build:

  ```sh
  python3 agent-bridge/website/prepare.py --release-manifest /path/to/r2/latest.json --write-config
  ```

  Its version and both archive URLs determine both DMG links and the displayed version in one step. This drops sizes belonging to the previous release. The manifest must contain both platforms, notes and signatures; page preparation is structural validation, not public availability or cryptographic verification. Complete R2 upload/public checksum verification before deploying this page. `--write-config` atomically saves the manifest-derived `downloads.json`, so later default preparation retains this release. Omit that flag for a preview that leaves the configuration untouched.

- Legacy `mac.source`, `mac.url` and `mac.architecture` remain supported for a single same-site package under `downloads/`. Preparation copies the actual file, verifies SHA-256 and computes its size. Local destination traversal, escaped paths and symlink escapes are rejected. An optional local `sha256` also verifies the configured digest.
- The hero button opens architecture selection when both packages are present. The arm64 and x64 anchors work without JavaScript. R2 files must carry an appropriate `Content-Disposition` header because browsers do not honor the `download` attribute for arbitrary cross-origin files.
- The current Mac build is a test release with a verified ad-hoc app signature, not Apple notarization. The page explains the macOS Privacy & Security override without guaranteeing its availability. Use a new download filename when rebuilding the same app version so caches cannot serve an older installer.
- iOS has no distribution URL and displays a non-interactive coming-soon status. Introducing an iOS release also requires updating the page and preparation validation.
- The original brand SVG is copied from `../desktop/src/assets/arclink-icon.svg`; keep the copy synchronized if branding changes.

## Static deployment

Run preparation first. Publish **only** `index.html`, `styles.css`, `main.js`, `assets/`, and any prepared local `downloads/` directory to the static web root. The R2 configuration requires no binary in the website deployment. Before switching the active website, verify both generated DMG URLs are public and their SHA-256 matches the released artifacts. The committed 0.1.3 R2 links describe the intended mirror; their presence in generated HTML does not prove that seeding/deployment is complete.

For legacy local downloads, the ignored binary must be deployed separately and `.dmg` should be served as `application/octet-stream` or `application/x-apple-diskimage`, with `Content-Disposition: attachment`. Page resources are relative and release downloads use absolute HTTPS URLs, so a subdirectory deployment is supported.

## VPS deployment: arclink.classktv.com

The authorized host is `89.45.45.158`. Keep credentials outside the website and release archives. Only the new ArcLink nginx site is managed here; preserve all existing virtual hosts.

Use `/var/www/arclink/releases/<release-id>/` for complete, immutable uploads and `/var/www/arclink/current` as the active symlink. Upload the static files listed above, including the DMG, into a new release directory and verify their checksums before switching. Create a temporary symlink beside `current` and atomically rename it over `current` with `mv -Tf`; retain the previous release for rollback. Switching back uses the same operation. The nginx worker must be able to traverse the release directories and read the files.

1. Ensure DNS points to the VPS and ports 80/443 are reachable. Create `/var/www/arclink/acme` independently of release directories.
2. Install `deploy/nginx-http.conf` as `/etc/nginx/sites-available/arclink.classktv.com` and enable only that file with a symlink under `sites-enabled`. Run `nginx -t` before reloading nginx. This bootstrap configuration serves HTTP without referencing a nonexistent certificate.
3. Obtain the certificate with the existing Certbot installation:

   ```sh
   certbot certonly --webroot -w /var/www/arclink/acme -d arclink.classktv.com
   ```

   Supply the certificate account details required by the host's existing Certbot setup. The ACME token path remains available over HTTP without redirection.

4. Replace the ArcLink site configuration with `deploy/nginx-https.conf`, run `nginx -t`, then reload nginx. It uses `/etc/letsencrypt/live/arclink.classktv.com/`, the host's existing `options-ssl-nginx.conf` and `ssl-dhparams.pem`. All non-ACME HTTP requests redirect to HTTPS.
5. Verify HTTPS, the HTTP redirect, a missing-file 404, `Cache-Control: no-cache` for HTML, and the DMG attachment headers/checksum. The configuration serves static files only; there is no SPA fallback.

Keep the host's Certbot renewal timer enabled. Webroot renewal must retain `/var/www/arclink/acme` and the port-80 challenge location; run `certbot renew --cert-name arclink.classktv.com --dry-run` to validate it. Ensure the existing successful-renewal deploy hook runs `nginx -t` and reloads nginx, adding a scoped hook if none exists. Never place the ACME webroot inside a timestamped release, since `current` will change over time.

## Verification

1. Run `python3 agent-bridge/website/test_prepare.py`, then prepare the intended release. For local packages, inspect the printed package hash; for R2, independently verify public availability and release checksums before deployment.
2. Run `node --check agent-bridge/website/main.js`.
3. Serve the site and check `/`, `/styles.css`, `/main.js` and `/assets/arclink-icon.svg` return HTTP 200; verify both architecture links/version without JavaScript.
4. Download both DMGs from their actual public links and compare SHA-256 with the released source artifacts.
5. Check desktop (1440 px) and mobile (390 px) layouts, keyboard focus, navigation anchors, FAQ and the unavailable iOS status.

The device UI is an explicitly labelled illustration, not a screenshot or an interactive remote client. This page does not collect personal data or use external fonts, analytics or network dependencies.
