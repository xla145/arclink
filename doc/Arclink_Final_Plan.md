# Arclink 最终产品方案

版本：v1.0  
日期：2026-11-04  
适用阶段：个人开发者、现有 Mac + iPhone 连接能力基础上的首版验证  
产品地址：https://arclink.classktv.com/

> 核心决策：以项目组织工作，以任务作为手机操作入口。Agent 由项目配置负责选择，App 主界面不提供常驻 Agent 切换器。先把一个任务可靠地交办、执行、交付，再验证常用任务能否带来重复使用与付费。

## 1. 产品定位

**Arclink 是独立开发者随身使用的项目任务助手：在手机上交办工作，让自己的 Mac 执行，并把结果带回手机。**

首个目标人群：已经在 Mac 上使用 Codex、拥有 iPhone、会在离开电脑时继续推进个人项目的独立开发者。

首版价值承诺：

- 不必每次选择 Agent、寻找工作目录、重新解释项目背景。
- 可以发送文字和图片，也可以重跑已经配置好的常用任务。
- 能分清任务有没有送达、是否正在执行、是否需要自己处理。
- 完成后拿到可阅读的结果和可下载的产物，而非只有本地路径。

品牌文案建议：**手机交办，Mac 执行，结果随行。**

功能成熟后再使用的延伸文案：**把常做的工作，收藏成手机上的一个按钮。**

### 1.1 经营目标与约束

- 目标是形成个人可维护、可获客、可盈利的小产品，不以综合 Agent 平台为首期目标。
- 第一版只承诺 Mac + iPhone + Codex。多 Agent 是架构预留，不是上线前提。
- 优先复用现有配对、连接、项目与会话能力，不重写整个产品。
- 尽量让用户沿用已有模型账号和本地环境，不经营模型额度转售。
- 配置复杂度、支持时间和版本兼容成本，必须纳入功能取舍。

## 2. 调研结论与方案依据

### 2.1 已观察到的竞争事实

| 类别 | 代表产品 | 对 Arclink 的启示 |
| --- | --- | --- |
| 官方远程入口 | Claude Code Remote Control、Codex 移动访问 | 远程聊天、任务跟进与审批难以独立形成差异化 |
| 综合开源客户端 | Happy、Happier、Yep Anywhere | 多 Agent、加密、会话列表、审批、Git 等已有大量供给 |
| 原生付费客户端 | Remodex、HAPI 原生 App | 安装便利和原生体验存在收费尝试，但不能推断其收入规模 |
| 消息平台桥接 | cc-connect、CodePilot | 中文和飞书等入口不是空白市场 |
| 专项监督工具 | Pushary、onpath、HELM | 审批中心、停滞检测、离桌监督也已有竞争 |
| 自动化与手机控制面板 | PocketHook、Touch Portal、Macro Deck | 按钮、快捷指令、远程触发本身不是独创功能 |

参考资料见文末。上述能力来自公开产品页面，不等同于安装实测结果。

### 2.2 用户反馈提供的线索

公开反馈中出现过审批未显示、后台返回状态过时、无法判断任务是否还在推进等问题。另有用户表示手机适合启动任务和解除阻塞，但复杂审查仍回到电脑完成。[6][7][8]

这些反馈支持优先建设可信任务状态与短操作流程，但不证明问题普遍存在。部分旧问题已经修复，不能用于宣传竞品当前缺陷。

### 2.3 最终选择

以可靠的项目任务闭环作为底座，用“常用任务 + 手机素材输入 + 结果交付”验证差异化。

不把截图验收、智能监督、团队协作全部塞入首版；它们仅在真实使用数据支持时再考虑。

### 2.4 尚未验证的商业假设

1. 用户存在每周重复执行的任务，并愿意保存配置。
2. 常用任务比在已有聊天里重新发一句话明显省事。
3. 手机直接获取产物会提升重复使用。
4. 用户愿意为便利和可靠性付费。
5. 开发者能够以足够低的支持成本维护该产品。

本方案是实施与验证基线，不代表已经找到产品市场匹配；不使用竞品标价、下载或星标推导收入。

## 3. 主要用户场景

### 场景 A：离开电脑后交办一次工作

选项目 → 输入文字或图片 → 发起任务 → 查看执行状态 → 必要时回答问题或审批 → 获取结果。

### 场景 B：重复运行常用任务

选项目 → 点常用任务 → 填必要参数 → 确认运行 → 获取结果。

初始模板只保留三个候选，最终由实际使用频率决定：

| 模板 | 输入 | 输出 | 默认边界 |
| --- | --- | --- | --- |
| 检查项目 | 检查范围 | 检查结果、失败摘要、报告 | 不自动修改或发布 |
| 生成发布说明 | 版本或变更范围 | Markdown 发布说明 | 只生成草稿，不自动对外发布 |
| 截图交办 | 图片与说明 | 已接收的任务或处理结果 | 默认等待用户明确选择是否开始执行 |

首期只要求一个模板完整跑通，其余不构成上线阻塞。

### 场景 C：继续已有任务

打开任务 → 查看此前进展 → 补充要求 → 沿用同一个会话继续。

不会因为重新进入 App、网络重连或项目默认 Agent 改变而创建新会话。

### 场景 D：电脑不在线

允许保存到手机，显示“待发送”。电脑恢复并不意味着所有旧任务应立即执行：首版默认由用户点击发送。后续若支持自动发送，必须提供明确的开启选项与过期规则。

## 4. 项目、Agent 与会话的关系

### 4.1 产品规则

**项目默认，任务可覆盖，会话保持，异常明确提示。**

| 层级 | 选择规则 | 首版处理 |
| --- | --- | --- |
| 项目 | 配置默认执行设备、目录与 Agent | 默认 Codex |
| 常用任务 | 未指定时继承项目；将来可以指定覆盖 | 预留字段，首版不展示多 Agent 选择 |
| 一次性新任务 | 采用发起时的有效配置 | 保存配置快照 |
| 已有会话 | 沿用创建时的 Agent 和上下文 | 不重新路由 |
| Agent 不可用 | 明确原因，等待或由用户处理 | 不静默替换、不自动重跑 |

### 4.2 App 交互原则

- 主界面不设常驻 Agent 切换器。
- 任务详情显示执行设备、Agent、项目和状态，保持可解释性。
- 项目默认设置主要在 Mac 端配置。
- 手机上的高级设置后续按需开放，不作为发起任务的必经步骤。
- 改变项目默认值只影响后续新任务，不改写现有会话。
- 不做基于任务内容的自动模型竞赛、跨 Agent 自动分工或失败后静默降级。

### 4.3 “创建 Agent”的准确含义

用户发起新任务时，系统创建任务记录和对应会话，调用已经安装、可用的 Agent。无需每次创建一个新的长期 Agent 实体。

新任务默认独立会话；“继续这个任务”复用原会话。把任务交给另一 Agent，应作为显式的新任务或接续操作，不能假设完整上下文天然兼容。

## 5. 信息架构与页面

手机底部导航只保留三个入口：**项目、任务、设置**。

| 页面 | 核心内容 | 主要操作 |
| --- | --- | --- |
| 项目列表 | 收藏项目、所属设备、在线状态、待处理数量 | 进入项目 |
| 项目详情 | 常用任务、最近任务、新任务入口 | 运行常用任务、发送文字或图片 |
| 新任务 | 项目、文字、附件、必要参数 | 确认提交 |
| 任务列表 | 需要处理、执行中、已结束 | 快速找到需要自己的任务 |
| 任务详情 | 状态、最近事件、对话、审批、执行信息 | 回复、审批、申请停止、查看结果 |
| 结果卡 | 摘要、产物、验证项、未验证项 | 预览、下载、继续修改 |
| 设置 | 已配对设备、通知、连接诊断、版本 | 配对、撤销连接、查看诊断 |

Mac 端负责：设备配对、项目目录授权、Agent 可用性检查、项目默认配置、常用任务配置和本地执行记录。

首页优先展示用户要做的事，不展示模型排行榜、Token 仪表盘或完整终端。

## 6. 常用任务设计

### 6.1 定义

常用任务是一个可重复执行的配置，包含项目、输入、指令、结果约定与操作边界。它不只是保存一条 Prompt，也不等于可视化工作流平台。

### 6.2 首版配置字段

| 字段 | 用途 |
| --- | --- |
| 名称与说明 | 让用户知道按钮会做什么 |
| 所属项目 | 确定执行目录和默认 Agent |
| 输入定义 | 仅支持短文本、长文本、图片及少量固定选项 |
| 指令模板 | 把输入与固定背景组合成任务要求 |
| 输出约定 | 指定文字报告或允许返回的文件 |
| 操作边界 | 是否允许修改、哪些步骤需要审批 |
| 版本 | 便于区分任务运行时使用的配置 |

首版由用户在 Mac 上手动配置；“从成功任务保存”可以先采用复制指令并人工确认。自动从历史对话提炼可执行流程暂缓。

### 6.3 执行原则

- 确定性的工作优先使用已验证步骤，需要解释或判断的部分交给 Agent。
- 用户输入不能直接拼接成未经处理的 shell 命令。
- 参数确认页用自然语言说明本次要执行什么。
- 常用任务的自动化不能扩大底层 Agent 的授权范围。
- 输出规范属于约定，需要验证实际产物存在，不能只相信 Agent 自报完成。

## 7. 任务生命周期与可靠性

### 7.1 状态模型

| 状态 | 含义 |
| --- | --- |
| 待发送 | 只保存在手机，电脑尚未确认收到 |
| 已接收 | 电脑已持久化任务，尚未开始 |
| 排队中 | 等待同项目的前一个任务结束 |
| 执行中 | Agent 已开始执行 |
| 等待你 | 存在待回答问题或待审批请求 |
| 已完成 | 执行已结束，结果已整理；不等于所有结果都经过验证 |
| 失败 | 已确认执行失败，显示原因与可选后续动作 |
| 已取消 | 已确认停止；可能保留此前已经产生的修改 |

连接状态独立展示：在线、重连中、离线、状态待同步。断线不直接把任务标记为失败，也不能继续显示确定无误的“正在执行”。

停止按钮先显示“停止请求已发送”，收到主机确认后再更新最终状态。主机不可达时明确提示尚未确认停止。

### 7.2 必须保证的行为

- 每次提交携带稳定的任务标识，主机持久化后确认接收。
- 重复提交同一个请求时返回已有任务，不重复创建执行。
- 审批关联具体任务、请求和状态版本，过期或已经处理的审批不能再次生效。
- 手机返回前台后重新核对主机快照与未同步事件。
- 通知仅提示有变化，打开后以主机最新状态为准。
- 无法确定有副作用操作是否已经发生时，不自动重放；标记待确认。
- 同项目首版串行执行，避免并行修改同一目录。

不能承诺外部操作端到端“绝对恰好执行一次”；首版通过去重、确认和保守恢复减少重复执行风险。

### 7.3 首版验证场景

锁屏返回、Wi-Fi 切蜂窝、主机掉线恢复、重复点击、审批后断线、停止确认、配置变化后继续旧任务、产物生成后断线下载。

在小规模验证中，任何确认的重复副作用执行、错误审批归属或任务串线，都应作为阻止扩大测试的缺陷处理。测试通过不是对所有网络与系统环境的永久保证。

## 8. 结果交付

每个任务结束后返回结构化结果卡：

1. 做了什么。
2. 实际产物与预览入口。
3. 执行过的检查及结果。
4. 未验证、失败或需要人工处理的事项。
5. 继续修改与查看详情的入口。

首版优先支持 Markdown、普通文本、图片，以及文件下载。复杂 Office 预览、原生 App 远程安装、大文件视频传输暂缓。

产物必须绑定任务与生成版本；不把某个路径下后来被覆盖的文件误当作之前任务的结果。对可返回目录做范围限制，不能允许任意路径读取。

主机离线时若产物未缓存，应显示暂不可下载。下载或缓存成功后才能承诺离线可查看。

## 9. 技术实施边界

本节是设计建议，未审阅现有代码，不构成对当前实现能力的确认。

### 9.1 职责划分

| 组件 | 职责 |
| --- | --- |
| iPhone App | 项目入口、输入、任务状态、审批、结果查看、本地草稿 |
| Mac 服务 | 项目配置、任务持久化、排队、Agent 调用、审批协调、产物管理 |
| 连接层 | 沿用现有优先直连与必要中继，保证鉴权和重连 |
| Agent 适配层 | 首版仅 Codex，统一事件与状态映射 |

主机任务记录是执行事实来源。App 缓存用于快速展示，但必须标注同步状态。

### 9.2 最小数据对象

| 对象 | 核心字段 |
| --- | --- |
| Device | 设备 ID、名称、授权状态、最近连接时间 |
| Project | 项目 ID、设备 ID、目录、默认 Agent、配置版本 |
| ActionTemplate | 模板 ID、项目 ID、输入定义、指令、输出约定、版本 |
| Task | 任务 ID、项目 ID、模板版本、输入、有效配置快照、状态、时间 |
| Session | 会话 ID、任务 ID、Agent 类型、底层会话引用 |
| Approval | 请求 ID、任务 ID、操作描述、状态版本、处理结果 |
| Artifact | 产物 ID、任务 ID、类型、文件版本、大小、可用状态 |

不需要首期建设微服务、分布式调度器或插件市场；优先在现有 Mac 服务中实现模块化任务管理。

### 9.3 权限与隐私表述

- 配对后仍需按项目授权目录；支持撤销设备授权。
- 保留底层 Agent 的审批机制，不用自然语言模板绕过权限边界。
- 直连与端到端加密是不同概念；是否实现端到端加密必须据代码和测试说明。
- 本地执行不等于模型数据不出设备；说明模型提供商、直连/中继和推送各自的数据流。
- 默认诊断不采集源码、Prompt 和产物正文。需要详细日志时由用户主动导出并检查。
- 不承诺电脑睡眠或关机后仍能执行。

## 10. 功能优先级

| 阶段 | 必须完成 | 不作为该阶段目标 |
| --- | --- | --- |
| P0：可靠底座 | 安装配对、项目绑定、Codex 可用性、图文任务、状态确认、审批、停止、结果卡、基本恢复 | 多 Agent、自动路由、复杂工作流 |
| P1：差异化验证 | 一个可配置常用任务、参数输入、重复运行、产物下载、少量真实用户测试 | 模板市场、自动生成流程、团队协作 |
| P2：留存后扩展 | 按数据选择分享入口、从成功任务保存、通知优化或第二个模板 | 无明确需求的跨平台扩张 |
| P3：有付费证据后 | 选择第二个 Agent 或更深入的垂直任务 | 同时支持所有 Agent |

明确暂缓：Windows、Android、多人权限、自动切模型、多 Agent 协作、生产自动发布、通用远程桌面、复杂代码编辑器、智能卡住恢复、客户验收门户。

## 11. 个人开发者实施计划

按关卡推进，不按完整功能清单推进。以下是投入建议，实际工期需要代码评估。

### 关卡 A：现有能力盘点

核对官网描述与真实实现：安装与公证、iOS 分发、审批是否闭环、断线后是否恢复、结果是否可下载。完成一次从手机发起到获取结果的真实任务。

通过条件：能说明哪些是已实现、哪些需要补齐；不以示意界面当功能证明。

### 关卡 B：一个完整闭环

选自己每周会做的任务，完成提交、接收确认、执行、结果与异常提示。先用自己的真实项目，不为演示创造需求。

通过条件：重复运行可用，网络异常不会导致无提示丢失或自动重复执行。

### 关卡 C：常用任务实验

以 7–10 个工作日作为该实验的投入上限，而非工期承诺。只做手动配置、少量参数和结果交付；超出上限则减范围。

通过条件：用户不需要重新找目录、补背景或找产物，就能再次完成同一类工作。

### 关卡 D：真实使用与付费

邀请 5–10 位已有 Mac + iPhone + Codex 使用经验的开发者，每人配置一个自己的重复任务，连续观察两周。先不扩平台、不增加大量模板。

## 12. 验证指标与停止条件

### 12.1 指标

| 指标 | 定义 |
| --- | --- |
| 首次独立成功率 | 无开发者一对一介入即可完成首个任务的人数 / 参与者人数 |
| 主动重复使用 | 第二周未受逐次提醒仍发起真实任务的人数 |
| 常用任务复用 | 同一用户再次使用已保存模板的次数 |
| 有效交付 | 任务产物被查看、下载或确认可用的次数 |
| 产品阻塞率 | 因 Arclink 连接、状态、审批等缺陷无法继续的任务数 / 已接收任务数 |
| 支持负担 | 每位活跃或付费用户所需人工支持时间 |
| 实际付费 | 完成付款并继续使用的人数，不以口头意愿代替 |

首期可通过用户自愿反馈与本地诊断记录收集，不需要搭建复杂分析平台。

### 12.2 小样本决策参考

以下为内部实验门槛，不是行业基准，也不足以推断整个市场：

- 第一组 5 人中若至少 3 人第二周主动重复使用，继续观察。
- 有用户愿意按明确价格付款，且付款后仍使用，才开始设计完整收费版本。
- 若主要需求都是偶尔遥控，常用任务无人复用，则保留轻量客户端定位，停止扩建任务系统。
- 若所有人都需要大量定制配置，缩减支持范围，不立即发展模板市场。
- 若用户无法说出比已有工具省掉了什么操作，不继续堆功能。
- 发现重复执行、审批串线或状态误导等关键缺陷，先修复再扩大试用。

## 13. 收费与成本

### 13.1 首次收费实验

建议测试 **¥99 买断当前主要版本**，不是最终定价。免费体验允许完整运行一个常用任务；付费权益可以是更多已保存任务与便利功能。

基本审批、停止、设备撤销等控制能力不作为付费锁定项。模型使用费用独立，提前明确。

持续中继与托管成本需单独核算，不承诺永久无限量服务。若后续采用订阅，应对应持续服务价值，而非只为了获得经常性收入。

### 13.2 经济约束

买断收入取决于持续新增销量，不能与订阅 MRR 混淆。以 ¥99 为例，售出 100 份的毛收入是 ¥9,900，尚未扣除佣金、税费、退款、基础设施与支持成本。

优先降低首次安装失败和人工配置时间。若每位买断用户需要长时间协助，先改进产品或收窄适用环境，再扩大获客。

## 14. 获客与官网

先触达自己能持续接触的独立开发者，不铺大量渠道。

首支演示只展示一个真实过程：

1. Mac 上配置一个常用任务。
2. 手机填入输入并运行。
3. Mac 执行，手机显示可信状态。
4. 手机收到可用结果。

向用户收集“此前怎么完成、现在省掉哪些步骤、为什么没有再用”，不只问喜欢哪些功能。

官网首屏建议：

> **手机交办，Mac 执行，结果随行。**  
> 选择项目、发送任务，或一键运行常做的工作。Arclink 调用 Mac 上已配置的 Codex，把进度与结果带回 iPhone。

只有相关能力实际完成后才使用这段完整文案。明确设备要求、电脑在线要求、支持的 Agent、下载状态与费用边界。将真实演示放在抽象口号之前。

## 15. 关键风险与应对

| 风险 | 应对 |
| --- | --- |
| 官方或免费产品覆盖常见功能 | 以真实任务的步骤减少与重复使用验证，不靠功能数量竞争 |
| 常用任务只相当于快捷 Prompt | 测量是否省掉项目定位、输入准备和产物获取；没有明显改善则停止 |
| Agent 升级破坏兼容性 | 首版只适配一个 Agent，保留明确支持版本和关键场景回归 |
| 失败恢复引发重复副作用 | 保守恢复、去重、状态确认；不确定时交由用户处理 |
| 原生后台和网络切换造成状态过时 | 主机持久化、前台恢复同步、明确过时状态，不依赖手机长连接存活 |
| 买断收入无法覆盖服务成本 | 限定权益边界，核算中继和支持成本，不承诺无限服务 |
| 产品范围持续膨胀 | 新功能必须对应重复出现的真实问题，并替换低价值工作 |
