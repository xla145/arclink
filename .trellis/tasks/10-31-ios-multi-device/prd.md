# iOS 添加与切换已配对设备

## 目标
在 ArcLink iOS 首页右上角增加设备入口，让用户添加多台电脑并在以后切换，持久保存配对列表。

## 已确认需求
- 首页右上角进入设备列表，标明当前设备，并提供添加设备入口。
- 复用现有扫码配对流程；添加新电脑不能覆盖其他已配对电脑。
- 点击已保存设备切换首页对应的项目、会话及连接上下文。
- 重启后保留设备列表与最近选中的设备。
- 保留 ArcLink 标题、现有内部标识与设备身份。

## 现状证据
- AppModel.swift 的 AppStore 目前只有单一 hostName/macEndpointId/bridge；Snapshot（约 591 行）持久保存一份项目、会话、消息与审批。
- pair(from:)（约 389 行）会在配对成功之前更新 hostName；新方案需要防止失败配对污染当前设备。
- finishPair（约 464 行）直接替换 bridge；connectAndRefresh 和 reconnectIfNeeded 的异步回调未按设备上下文过滤，快速切换需防旧回调覆盖。
- AgentBridgeApp.swift:23 使用单一 NavigationPath；切换设备需要清理旧设备页面路径。
- AgentBridgeApp.swift:51 已有 Route.devices 和 DeviceListView，可复用设备入口。
- 当前 send/resolve 的会话与审批行为仍以本地模拟为主，本任务不扩展远程 Agent 能力，也不能将本地记录宣称为远端实时数据。

## 验收方向
- 添加 A、B 后两者均在列表中；重复扫码同一 endpoint 不生成重复行。
- 从 A 切换 B 后不显示 A 的项目、会话、消息或审批；再切回 A 能恢复 A 的本地记录。
- 新配对失败或取消不丢失已有设备及当前上下文。
- A 的延迟连接结果不会更新已切换到 B 的状态。
- 旧版单设备数据无损迁移；不持久信任旧 online 状态。
- 重启后恢复设备列表及最近选择，真实连接成功后才显示在线。

## 连接策略
用户明确选择同时连接多台设备。App 在前台运行时，对所有已配对且有有效 endpoint 的电脑并行维持连接；切换仅改变当前展示上下文，不断开其他电脑。每台电脑独立显示连接中、在线、离线或失败，单台失败不阻塞其余连接。新配对成功后选中新设备；取消或失败保持原选择。
iOS 挂起后不保证连接持续存活，回前台检查并恢复全部设备连接。本轮不新增 APNs、后台保活或跨设备统一审批消息中心。现有真实 Control RPC 状态按设备更新，本地模拟会话能力保持原有范围。
已有解除配对入口只影响选中的设备；解除后选择另一已保存设备，无设备时返回引导页。其余设备的记录与连接不受影响。


## 范围边界
不改桌面配对协议，不重做远程 Agent 会话传输，不修改 bundle ID 或手机身份密钥。允许调整 Rust 客户端网络端点的共享生命周期以支持真实并发。

## 补充验收
- 至少两台测试主机同时连接且可分别调用 Ping/ListAgents；切换所选设备不会关闭另一条连接。
- 一台主机掉线不影响另一台在线；恢复前台逐设备重新检查状态。
- 配对第三台期间，已有连接可用；移除一台仅关闭该台连接。
- 单设备旧数据迁移后原记录仍可访问；无 endpoint 的旧 LAN 记录保留并提示重新扫码补齐连接信息，不伪造在线。
- 设备列表展示当前选择及各台独立状态，添加入口复用扫码，首页产品标题保持 ArcLink。

## 首页状态展示调整
用户补充希望将首页“在线”等状态并入标题区域。主标题保持 ArcLink，紧凑副标题显示当前电脑名称及真实连接状态；右上角保留设备入口。移除重复的主机/连接展示，服务状态若含独立语义则保留。状态必须有文字，不只依赖颜色；长设备名截断且不挤压按钮。切换设备后副标题随所选设备更新，不代表全部设备在线。
