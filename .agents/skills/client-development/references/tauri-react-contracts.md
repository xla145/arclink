# Rust / React 桌面契约

这是实现与审查清单，按当前任务涉及部分使用。不要为不涉及的进程、托盘或权限功能预建框架。

## Tauri 2 与类型边界

确认当前项目的 Tauri 主版本，查同版本 API 和权限机制。不要混用 Tauri 1 配置、插件调用与 Tauri 2 capabilities。

将 UI 需要的操作设计为具名、参数受限的 commands；Rust 使用 serde DTO，React 在统一桥接模块调用。类型可由工具生成或用契约测试维护；不要让每个组件各自猜 JSON 字段。错误至少保留可判断的类别和可呈现消息。

Rust 的 u64 可能超出 JavaScript 安全整数范围；对于序列、时间或 ID 明确边界，必要时传字符串。区分缺失值、null 和空列表。事件携带足够的设备/会话/进程代次标识，避免把另一轮结果写入当前状态。

Tauri capabilities 和插件权限按功能最小化。Rust 仍验证参数，不能仅依赖 React 禁用按钮。不要把任意 shell、文件路径或不受限 RPC 转发暴露给 WebView。WebView 使用本地打包资源并限制外部导航；外部链接通过明确的系统打开动作处理。

## React 状态与展示

分清服务端权威状态、待处理操作、临时表单和可推导展示值。不要复制同一份状态到多个 store 后分别更新。刷新失败后让关键操作知道原状态已过期。

请求有生命周期标识；旧进程/设备或旧请求响应不能覆盖新状态。组件清理时取消订阅与定时器，防止 React 开发模式重复挂载造成多个轮询器。副作用启动由单一所有者负责；服务端也应拦截重复启动。

保留操作结果未知与失败的区别。重试时复用已有幂等键或先查操作状态；没有幂等能力时不能自动重发变更。示例数据只用于明确的 preview/test 入口，真实运行缺失桥接时显示不可用，不静默回落成模拟成功。

## 托盘与窗口

- 托盘点击应显示/聚焦正确窗口；按当前屏幕可用区域定位并处理缩放和屏幕边缘。
- 关闭/失焦隐藏面板和退出应用是不同动作。依据产品约定处理；收起菜单栏面板通常不终止服务。
- 长列表有高度上限和滚动，弹层不被窗口边界裁切，键盘与可访问名称可用。
- macOS 激活策略、Dock 显示、托盘模板图标与最小系统版本在原生环境验证；不要用网页模拟替代。
- 登录启动由明确用户操作触发，并呈现 OS 的实际注册/批准状态。实现可用适配平台插件或本地 API；未验证时不假装成功。

## 子进程与本地管理通道

只有在现有架构确有 daemon/sidecar 时使用：

- 根据 Tauri 实际打包位置解析可执行文件，不依赖开发时绝对路径或交互式 shell 环境。使用显式程序与参数，配置路径选择不经过 shell 拼接。
- 分配进程代次，在首次 await 前抢占 starting 状态；结束与回调检查所有权，重启后旧代次不能改变新状态。
- GUI 只停止自己持有的子进程句柄。数据库锁冲突不是强制杀掉其他 daemon 的理由。
- 对 JSONL/二进制帧先限定长度，增量处理，再解码；串行化 stdin 写入，避免大于 PIPE_BUF 的并发消息互相穿插。
- stdout 机器协议与 stderr 日志分离。EOF/异常退出及时失败所有 pending 请求；队列、响应、日志和未完成消息都有上限。
- 日志不记录令牌、密钥和完整敏感响应。系统凭据放 OS 凭据存储，不放 localStorage、前端包或明文配置。
- 退出遵循明确产品约定：需要停止时先优雅关闭、等待退出，再对仍拥有的活进程做有限超时回收。会中断活动工作的动作说明影响。

## 构建与迁移

复用已有 Cargo workspace 和 Node 管理器。为新 Tauri crate 明确 workspace 成员关系和 target 输出位置，避免意外生成互相冲突的锁文件/输出目录。Node lockfile 与 Cargo.lock 都保持可重现。

迁移时检查：启动入口、测试、图标资源、应用标识、sidecar 路径、旧框架依赖、构建脚本、使用说明和现有产物。确认新产物实际包含 React 资源与 Rust/Tauri 可执行文件，而不是仍在分发旧客户端。

本地调试包、ad-hoc 签名、Developer ID 公证是不同交付级别。仅声明已完成的级别，不自动发布、安装或启用登录项。

## 有价值的验证

按变更选择：

- DTO 的成功/null/错误响应与数值边界；畸形、超长、分片消息。
- 双击启动只产生一个进程；重启后旧回调被忽略；EOF 能结束 pending 请求。
- 请求超时不重复触发副作用；断线后刷新再启用关键操作。
- React 真实用户操作能触发正确命令；错误不会显示成功状态。
- 实际托盘可打开/隐藏，退出清理符合约定；浏览器预览无法证明这些原生行为。
- 打包后仍能找到 helper 和静态资源，日志与数据路径可写且不覆盖用户无关数据。

通过这些行为断言验证契约，不通过只搜索某个字符串或重写一份相同状态机来“验证”实现。
